# Internal implementation contract

Single Tauri command: `manager_request({request: {action, ...args}}) -> Promise<any>`. All JSON uses camelCase. Root handles serialization, DB and dispatch. State mutations must call `manager.save()?`.

## Shared Rust model (owned by root)
`Manager { pub data_dir: PathBuf, pub state: State, pub previews: HashMap<String, Value> }` (DB field private).
`State { pub skills: Vec<Value>, pub sources: Vec<Value>, pub connections: Vec<Value>, pub settings: Value }`, serializable and cloneable. `manager.snapshot() -> Value`, `manager.save()->Result<(),String>`, `manager.skill(id)->Result<Value,String>`, `manager.upsert_skill(Value)`, `manager.id()->String`. Shared `now()->String`.
Each subsystem `pub fn handle(m: &mut Manager, req: &Value) -> Result<Option<Value>, String>` returns None for unknown actions. Dispatch gives merged remote file and external-resource actions their dedicated handlers before legacy local/remote fallthrough. Filesystem effects and their persisted receipts remain ordered by each transaction contract. Detached task workers have no database writer; their save hooks merge into the one live Manager before acknowledgement. The versioned sections below retain earlier contracts; later sections refine them.

## Skill record
`{id,name,displayName,description,version: string|null,localPath: string|null,readOnly:bool,sourceId:string|null,remotePath:string|null,repo:string|null,branch:string|null,commit:string|null,baselineCommit:string|null,baselineHashes: Record<path,sha256>,runtimeFiles:string[],runtimeConfirmed:bool,status:string,lastChecked:string|null,error:string|null,private:bool}`. Local registration sets baseline unknown. `status`: local_only, remote_only, synced, local_modified, remote_updated, both_modified, docs_updated, unknown_baseline. Extra fields allowed.
Source `{id,kind:"github",repo:"owner/repo",branch,commit,private,lastChecked,error}`. Connection `{id,skillId,client,path,target,discovered:true,linked:true,verified:false}`.

## Actions
- get_state -> State plus dataDir
- scan_local {path} -> `{skills: SkillDraft[], warnings:string[]}`; no registration
- add_local {paths:string[]} -> State
- add_github {url} -> State, recognize catalog or recursive SKILL.md
- associate {skillId,sourceId,remotePath} -> State; explicit manual choice remains available
- auto_associate -> State; also runs after source/local registration and full refresh. Require verified unique internal names plus matching directory identity or verified runtime bytes; retain local IDs/paths/connections, remove only redundant unconnected remote placeholders. Never infer installation history from association.
- forget {skillId} -> State, do not delete files; require disconnect first
- refresh {skillId?,skillIds?:string[],localOnly?:bool} -> State; scoped local hashes/remote check, failures recorded per source. Scoped checks do not discover or merge unrelated records. Local-only refresh retains failed/pending remote verification.
- get_files {skillId} -> `{files:[{path,size,hash,runtime:boolean}],runtimeConfirmed,requiredFiles:string[],optionalFiles:string[],requiredReasons:Record<path,string>,warnings:string[]}`
- read_file {skillId,path} -> `{content}` (local text, size bounded)
- get_document {skillId,version:"installed"|"latest",path?} -> `{markdown,baseUrl,source,checkedAt,private}`; relative image/file navigation must use authenticated backend for private sources (get_doc_asset)
- get_doc_asset {skillId,version,path} -> `{dataUrl}` size bounded
- preview_install {skillId,targetPath,files:string[]} / preview_update {skillId} -> Preview
- apply_install / apply_update {previewId} -> State; preview ID one-shot, reject filesystem or remote drift
- preview_push {skillId,files:string[]} -> Preview
- apply_push {previewId,message} -> State; preserve omitted README; reject remote advance
- connect {skillId,client:"codex"|"claude"|"cursor",targetPath?} -> State; default user dirs .agents/skills, .claude/skills, .cursor/skills; link only, never overwrite existing folder
- disconnect {connectionId} -> State; verify actual link target and detach link only
- export {skillId,destination} -> `{path}`; ZIP runtime + provenance, never overwrite
- set_token {repo,token} / delete_token {repo} -> `{saved:true}`; OS credential manager only
- set_settings {settings:{checkIntervalMinutes:30,editorPath?:string}} -> State
- open_local {skillId} -> `{opened:true}` (root implementation)
- open_folder {skillId} -> `{opened:true,path}`; registered canonical local folder only, independent of editor configuration

Preview `{id,kind,skillId,summary,files:[{path,change:"added"|"modified"|"deleted"|"unchanged"|"conflict",local?:string,remote?:string}],warnings:string[],canApply:bool}`. Extra private fields only in manager.previews, never send tokens/content beyond intended diffs. Runtime classification supplies the default when no manifest is declared; include required SKILL.md and licenses, reject missing dependencies/unsafe paths. Existing manual and legacy confirmed scopes remain exact; a new unresolved requirement is reported for adjustment. Updates with any local modifications refuse applying and direct to external editor; no automatic merge. Docs-only no runtime reinstall. Reject readonly writes.

Runtime selection uses shared reader-based dependency classification for local and immutable remote bytes. Required entry/config/license/resolved dependencies remain selected; ordinary docs are optional unless actual runtime references require them. Deselection preserves local files and historical receipts. Update safety compares only the mutation scope; upstream deletion requires current management plus genuine baseline history. New files that differ locally remain protected.

`comparisonLocalHashes`, `comparisonRemoteHashes`, `comparisonScope`, `comparisonRuntimeSelection`, `comparisonDocHash` and observation timestamps store first/current comparison evidence separately from `baselineCommit`/`baselineHashes`. First differing association stays unknown; later observations distinguish local/remote/both changes. `changeDetails:[{path,change,side}]` and comparison/association notes are concise display evidence. Only complete confirmed equal runtime can certify a fixed remote baseline; partial pushes retain unsubmitted differences and failed post-write reads report submitted-but-pending status.

Full and local-only checks refresh a valid local SKILL.md declared version for display (root version, then metadata.version). Missing/unreadable/invalid declarations retain the existing version. This display refresh never changes identity, provenance, installation history or content-based synchronization evidence.

## Shared filesystem helpers (local.rs, agent-owned)
`pub fn canonical(path:&Path)->Result<PathBuf,String>` resolves root links, `pub fn files(root:&Path)->Result<BTreeMap<String,String>,String>` returns relative paths -> SHA256, rejects interior links/reparse traversal, excludes .git and manager artifacts, `pub fn safe_join(root:&Path,relative:&str)->Result<PathBuf,String>`, `pub fn draft(root:&Path)->Result<Value,String>`.

## Transactions (root-owned transaction.rs)
`pub fn apply(data_dir:&Path, root:&Path, expected:&BTreeMap<String,String>, writes:&BTreeMap<String,Vec<u8>>, deletes:&[String])->Result<String,String>` verifies entire expected runtime snapshot (missing too), saves original affected bytes and a journal under data_dir/recovery, applies same-dir temp files + rename, rolls back on any failure. Existing unknown files preserved. Does not remove recovery history. `pub fn recover(data_dir:&Path)->Result<Vec<String>,String>` restores incomplete journals on startup. No outside-root paths or ancestor links allowed.

Local agent owns local.rs and local tests. Remote agent owns remote.rs only (including pure comparison tests), can ask root to add dependencies. Frontend agent owns src/App.tsx, src/styles.css, src/main.tsx, src/vite-env.d.ts. Root owns config, model.rs, lib.rs, transaction.rs, tests/docs/build.

## v0.1.9 task scheduling and history

`start_task {request:BusinessRequest,label?,origin?,foreground?}` returns `{task}`. `list_tasks`, `get_task {taskId}`, `cancel_task {taskId}`, `clear_task_history`, `prepare_close` and `cancel_close` are control actions. Business requests retain their existing preview/apply contracts. States are queued/running/succeeded/failed/cancelled/interrupted; origin is a navigation target, never an executable replay request.

Independent workers operate outside the global state lock. Content mutations serialize by canonical Skill path, writes to the same repository/branch serialize, and client operations conservatively serialize by client resource. Metadata categories/favorites remain independent of content inspection. Resource locks and post-worker field patches preserve concurrent live fields; snapshots expose monotonic `stateRevision`, and nested snapshots rebase to current live state. Read-only work does not save stale whole-state copies over edits. Read completions are bound to their original Skill, tab, version and request generation.

Queued tasks can cancel; running reads and previews stop cooperatively at safe boundaries. A running blocking HTTP request first returns or reaches its timeout. Critical writes cannot cancel midway, and writes are never replayed from history. Closing rejects new work, cancels queued/cancellable tasks and waits for active critical writes, then flushes UI preferences; a failed close can be cancelled to restore normal task acceptance.

The existing SQLite stores at most100 terminal task metadata records, not bodies, tokens or business requests. In-memory current-session results are available by task ID; restarted results are expired. Previously unfinished records become interrupted and never resume a write automatically. Clearing history removes terminal records only. Existing state reads do not implicitly launch a client filesystem scan; explicit/initial task flows request checks.

## v0.1.9 network and immutable reads

`get_network_settings` returns public mode/proxyUrl/hasProxyCredentials. `set_network_settings {settings:{mode:'auto'|'direct'|'manual',proxyUrl?},proxyUsername?,proxyPassword?,clearProxyCredentials?}` persists public configuration and OS-keyring credentials separately. `test_network` returns small public API/raw status and timing without a GitHub token. Proxy addresses reject embedded credentials and query strings; the application does not alter system proxy settings or evaluate PAC scripts.

Use a shared reqwest pool per transport configuration, with10-second connection and30-second request timeouts. Windows static system/environment proxies, direct and explicit HTTP/HTTPS/SOCKS5/SOCKS5h are supported. A process-only64MiB LRU and in-flight coalescing reuse immutable metadata/bytes; repository metadata lasts15 minutes, while branch checks use conditional GET/ETag rather than a stale branch TTL. Keys bind repository, authentication identity and credential epoch. Token change/authentication denial invalidates affected evidence; no response-content disk cache is created.

REST has one active global permit and waiting foreground priority, while unauthenticated public raw reads permit up to four. Only GET connection/timeout/502/503/504 failures retry once after a cancellable0.5-second wait; POST/PATCH never retry blindly. Server rate-limit guidance is retained as deferred failure information. Downloaded bytes must match immutable tree length and standard Git blob SHA-1 before entering cache. Ordinary comparison may seed remote objects from matching local bytes; independent post-upload readback/cleanup always bypass cache and local-byte shortcuts.

## v0.2.0 workspace, page state and lifecycle

`manager_request` uses the invoking Tauri webview's actual window label. `WorkspaceSystem` owns windows, stable pane IDs, transfer registration and application close coordination; it shares the existing `TaskSystem` and live Manager. A new native window does not create another database writer, HTTP pool, credential store or periodic check loop. Workspace controls are handled before business dispatch; the backend injects the actual window/pane origin rather than trusting a caller-supplied window label.

Controls: `workspace_get`, `workspace_open_pane`, `workspace_update_pane`, `workspace_activate`, `workspace_focus_pane`, `workspace_close_pane`, `workspace_save`, `workspace_set_pane_runtime`, `workspace_get_pane_runtime`, `workspace_detach`, `workspace_move`, `workspace_ready`, `workspace_focus`, `workspace_reset_layout`, `workspace_close_intent`, `workspace_close_ack`, `workspace_close_status`, `workspace_finish_close`, `workspace_cancel_close`. Business request/preview/apply contracts remain in force.

Each window has a persistent home pane plus detail/operation/runtime/export/preview/receipts/audit/task/local/github/associate panes. Business tabs reorder; detaching creates a normal resizable native window, and moving returns a pane to the main window. The source keeps ownership until the target has mounted the pane, accepted its runtime and acknowledged the transfer. Failed/unacknowledged transfers retain the source. The page's task origin follows the stable pane ID through transfer; no business request is restarted merely to move its view.

The existing SQLite gains `workspace_state` for whitelisted navigation metadata: pane identity/kind/title/Skill target, view/section/document/version, scroll and outline/fold state, active tab, window geometry and revision. It stores neither document/preview bodies, tokens, executable request payloads nor arbitrary frontend objects. Restored transient operation pages set `reviewRequired`; they must read/re-preview before applying. Invalid saved layout reports a failure rather than overwriting it with empty data. Reset layout clears saved window geometry and recenters/resizes existing windows; sidebar layout remains its existing setting.

Pane runtime is process memory only, bounded to8MiB per pane with credential-field rejection. The frontend captures the originating page's current document/file/source state, inventory/preview, attachment choices, operation drafts, scroll/folds, pending task IDs and `ExternalManagementDraft` before transfer. The target reads current runtime for each incoming transfer, including a return to a previously visited window. Initial draft seeds apply once, not on ordinary live snapshots; inactive tabs remain mounted. Optional attachments start unchecked and clear for the successfully exported operation, including its original detail pane; management selections do not become export choices.

`state-changed` exposes monotonic `stateRevision`; `workspace-changed` and `workspace-activate` coordinate shared navigation. Inventory identities include local path, source/repository/branch/path/commit, local/baseline evidence, runtime choice and external bindings. Read results retain origin Skill/pane/section/version/generation. Task registration acknowledgement and unconsumed completed results survive transfer; result consumption updates only its matching target, with no duplicate apply or focus change to an unrelated active page. Concurrent previews retain independent one-shot IDs.

Theme/font/zoom settings are shared across windows; page scroll, outline expansion, file-group folds and unsaved mapping choices remain page-local. Global shortcut handling respects editable controls and blocking confirmations. `Ctrl+Tab`/`Ctrl+Shift+Tab` switch tabs, `Ctrl+W` closes the current business pane, home stays open. Outlines collect only headings and tagged structural sections within one pane, expand target ancestor groups and scroll its own main scroller.

Closing a nonfinal native window flushes its state and closes only that window; other windows and shared tasks continue. Closing the last window or exiting all coordinates acknowledgements from every affected window, prepares global task shutdown, then requests a second final flush after cancellable reads stop and critical writes finish. A failed acknowledgement/save/shutdown keeps windows open and restores task acceptance on cancellation. Normal closing persists layout/preferences; abrupt process termination or power loss cannot guarantee the last unsaved UI draft.

## v0.2.0 dual-source references, batch management and export closure

Dependency `role` is `required|optional|environment|history`, independent of `referenceKind` (`file|directory|package_file|skill_alias|command`). Legacy alias presentation normalizes to environment while retaining the actual alias type. A client command such as `/approve` is not a missing file; a real slash path such as `/a/file.json` remains a file candidate. Current-Skill directory and package-file aliases deduplicate rather than introduce a second copy; irrelevant bind/pack controls are disabled with a reason while purpose/reference information stays visible.

`local` and `remote` evidence separately describe availability, path, digest/readability, actual commit and any read error; `effectiveSource` identifies usable local/GitHub content. The remote status distinguishes unlinked/unread/error/missing/available; failed or unrequested remote reads never certify absence. Exact relative reference mappings use only the associated repository and immutable commit, including ordinary resources outside its Skill folder. Absolute-machine or basename-only matches remain explicit candidates. Ambiguity requires user selection; no cross-repository or latest-branch guess silently binds a reference.

- `get_external_dependencies` / `check_external_dependencies {skillId,includeRemote?,remoteCommit?}` -> `{skillId,items,summary}`; `includeRemote` defaults true, false is local-only evidence.
- `bind_external_dependency {skillId,dependencyId,role?,path?,source?:'local'|'github',repositoryPath?,remoteCommit?,expectedFingerprint?}` -> report plus `stateSnapshot`.
- `batch_external_dependencies {skillId,operation:'role'|'bind'|'remap'|'recheck',items:[{id,expectedFingerprint,role?,path?,source?,repositoryPath?,remoteCommit?}],includeRemote?}` -> report plus `results:[{id,status:'success'|'error',error?}]` and `stateSnapshot`.

Bindings use only an explicitly selected ordinary local file or validated path in the same associated fixed-commit repository. Binding/remapping preserves role; remap removes the previous source override rather than erasing purpose. Mutating batch items revalidate their expected semantic fingerprint against a fresh report, stage valid choices and persist them together through the existing save hook; failed/stale rows remain unchanged with per-item errors. A further pre-save semantic check rejects changed references. Recheck reads evidence without saving a role/binding. `Skill.externalBindings` stays in existing SQLite; no source-side manifest is added.

The external management UI exposes `initialDraft`/`onDraftChange` with `ExternalManagementDraft = {query,filter,managed:string[],batchRole,mappings:[{id,source,path,repositoryPath,remoteCommit}]|null}`. This is bounded in-memory page runtime, seeded only on mount. Search/filter/range selection, batch mapping preview and partial-failure retry remain separate from optional ZIP selection. The callback effect tracks owned draft fields via a callback ref, avoiding snapshot resets and parent-render loops.

`get_files {skillId}` remains the fast offline local inventory. `get_files {skillId,includeRemote:true,remoteCommit?}` adds the shared dual-source evidence and computes `exportRequiredFiles`/`exportError` from the same pinned mixed reader used by export. Local runtime selection and `runtimeConfirmed` still describe installed local files; a remote-only necessary resource appears in the required export group without pretending to be installed or confirming historical baseline. An external recheck replaces the complete inventory/commit/export status together, not just its dependency rows.

`export {skillId,destination,extraFiles?,remoteCommit?,externalIds?}` independently computes the minimal necessary closure. Matching local bytes take precedence; missing necessary package files and exact same-repository external resources can be read from the fixed commit directly into ZIP. `extraFiles` and optional external `externalIds` are explicit per-export selections; necessary resources are default included. Deduplication preserves existing package paths; outside-package files use virtual `external/<stable-id>/<filename>` entries. GitHub is bounded4MiB per object and32MiB aggregate remote/external content; existing large local assets remain streamed.

Final ZIP preflight uses the existing `private_resource` filename/path predicate uniformly on package logical names, actual local targets and original repository paths before remote reads. Recognized credential/private paths cannot bypass the guard through relative package names or bindings. This does not broaden that predicate or introduce content scanning; ordinary configuration/templates keep their existing treatment. Whole directories, environment/history roots and other Skills do not silently become bundle resources. Expected source/canonical identities and digests are rechecked before successful output.

Export creates only the selected final ZIP, with provenance inside it; no extracted resource tree, source copy, resource sidecar or downloaded local attachment is created. Exact static prose conversions affect ZIP bytes only; scripts/dynamic/partial conversions retain environment-required portability. Existing ordinary Manager SQLite saves remain distinct from export resource output. Neither export nor source availability updates an install event or proves model invocation. v0.2.0 final candidate verification is in progress; this contract is not a test-pass count.
