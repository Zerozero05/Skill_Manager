# 使用与恢复

下方按版本保留的章节记录当时的变化；当前操作入口以本页 v0.2.7 说明为准；下方版本章节保留历史背景。


## v0.2.7：快捷键、颜色与精简布局

技能库工具栏“快捷键”按当前列表或卡片显示实际按键。在按钮上按 Enter 或空格打开；Esc 关闭并返回按钮，点击外部也可关闭。窗口较小时浮层自动翻转、限高；内容可滚动。按向下键或 PageDown 进入说明正文后，可用方向键、PageDown、End／Home 查看完整说明，不改变技能选择或主页面滚动。

分类标签改为八种实心颜色，侧栏与颜色选择器保留对应色点。每个Skill仍只有一个主分类，颜色只改变外观；筛选到某一分类时，不逐行重复同一标签，分类仍在详情中。原有名称、收藏、归类、拖动和 Ctrl＋Z 用法保持。

夜间采用炭黑页面、石墨灰卡片和输入框；明亮采用浅灰页面与白色内容区；护眼采用较低亮度暖灰米色。正文与次要信息分别调整颜色，清楚显示按钮边界、禁用原因和键盘焦点。沿用原有主题、字号及缩放设置，不会启动时重置。

界面减少重复标题、宣传说明及空占位。未知版本在列表使用“—”，卡片不占位；有实际版本或连接时继续显示。来源文件夹可用图标打开，悬停显示完整路径。普通说明在对应折叠区查看；真实错误、来源异常、完整目标路径、必要文件与可选范围仍可查看。既有预览、上传／下载、ZIP选择、恢复、客户端连接、目录与多窗口操作保持。标签栏始终预留细横向滚动槽，任务徽标变化不挤压下方内容；没有设置固定裁切高度，仍可横向查看标签。

## v0.2.6：卡片、分类颜色与保存位置

技能库可以切换列表、卡片和分栏详情，沿用当前保存的默认视图。切换不清空筛选、排序、分页和本页选择。卡片复选框负责选择，名称打开详情，星标收藏；已选卡片或拖动手柄可一起拖入左侧分类。方向键移动焦点，Shift范围扩选，空格勾选，Ctrl＋A选择本页；工具栏“快捷键”可随时查看。

分类菜单提供“设置颜色”。创建或编辑分类可选八组主题色，分类仍为每Skill一个主分类，颜色和名称一同保存。原有无色分类直接显示不同默认色，启动不会补写；真正编辑分类时原子保存，Ctrl＋Z仍可连续撤销分类、归属和收藏。

每次新下载Skill或导出ZIP，都明确选择“使用默认位置”或“自定义位置”。页面显示完整本次目标；新操作不自动沿用上一次选择。选择窗口取消不启动任务、不创建空输出目录，已有目标不覆盖。ZIP默认名为Skill名.zip；默认导出文件夹在最终内容证明通过后才创建。操作标签移窗保留已经选好的目的地；默认设置变化需重新选择。已有Skill的更新、补齐和附件恢复仍使用原目录，避免新增副本。

客户端名称可直接打开对应Skill详情；“连接详情”在原位置展开／收起。主菜单“断开连接”只解除入口链接，原文件保留；“高级操作”内“忽略此连接，客户端继续可用”只忽略管理记录，入口保留。实际使用记录仍由用户确认，不会自动运行模型。

设置目录位于左侧；窄窗口通过同一按钮展开，按当前栏高定位。目录跳转露出完整目标标题，扩大字号和缩放后也保持当前窗格内滚动。必要文件与可选文件的ZIP勾选含义、预览核验及失败恢复继续沿用既有规则。


## 技能库列表与查找

默认使用紧凑列表，名称与用途、来源、状态、版本及常用操作显示在同一行。底部可选择每页20、50或100项，并查看结果总数和当前页码。

搜索覆盖全部已登记Skill，不限当前页。输入多个空格分隔的关键词时，每个词都需要匹配，词可以分别出现在名称、用途、仓库、本地路径或远端路径中。例如输入“写作 仓库名”，可同时缩小用途和来源范围。搜索或筛选改变后回到第一页；无结果时可用“清除筛选”恢复。

来源可选全部、本地、GitHub或已关联；状态可选需要关注、远端待下载、本地待上传、双方变更或内容待核对等。排序支持名称、状态优先和最近检查。列表／卡片／详情视图、每页数量和排序自动保存，独立于显示设置。

顶部将远端Skill条目与GitHub仓库分开计数：一个仓库可以包含多个Skill，仓库数按地址去重。本地和远端统计都包含已关联项，“已关联”单独显示两者的交集，不应将这些数字直接相加。

列表行中的“编辑”调用已有编辑器，“更新”先比较差异，“下载”先选择运行范围和保存位置。点击名称或“查看”打开Skill详情标签，继续提供说明、文件、来源与连接、上传修改、分享和导出等操作；点击“工作台”即可返回列表，不必先关闭详情。

来源列中的本地文件夹入口打开Skill真实目录，不受编辑器配置影响；GitHub入口打开该Skill所在分支与目录。悬停可查看完整路径；详情的“来源与连接”中也提供相同的直达入口。

工具栏的“详情”切换到原有分栏视图，左侧选Skill、右侧阅读完整内容。从变化页点击“查看详情”时会定位目标；目标被技能库筛选排除时，会清除筛选并跳转到目标所在页。紧凑列表纵向随整页滚动，表内只保留横向溢出访问；小窗口或高缩放下仍可滚动到分页和操作入口，详情可独立滚动。

## 标签页、独立窗口与目录

详情、导出、文件范围、操作记录、预览和检查结果可作为业务标签打开。工作台标签保留主列表与侧栏，可随时切回继续浏览；切换标签不会重新执行当前操作。拖动业务标签可调整顺序，Ctrl＋Tab切换下一个、Ctrl＋Shift＋Tab切换上一个；Ctrl＋W或标签右侧关闭按钮只关闭当前业务页，工作台不能作为普通业务标签关闭。

需要并排查看时，点击标签栏“移至独立窗口”，或将业务标签拖出当前窗口。用Windows标题栏拖动独立窗口，用窗口边界／角调整大小；点击“移回主窗口”合并回去。目标窗口完成载入前原页保留，移动失败不会丢掉原页面。这是原生窗口，不是在主界面叠放一个始终遮挡列表的详情浮层。

页面顶部的“目录”默认精简显示，可随时展开或收起。它按标题层级列当前页的说明、文件分组以及提供标题的引用和来源区域；文件页的必要、可选包内、可选外部及环境与参考四组分别可定位。点击后展开目标及其上级折叠组，等待内容布局后将完整标题定位到可见位置并短暂高亮，不跳到另一个Skill或标签。内容区采用一层主要纵向滚动，另一侧面板的位置保持。窄面板中目录浮在内容上方，选定后收起；Esc收起目录并回到入口。长文件名、同名引用和分组数量变化不会共用错误的目录或折叠位置。

本次运行中，标签保留自己的说明／文件页签、滚动、目录与分组折叠、筛选和未提交的路径绑定草稿；移出再移回也沿用这些状态。本次ZIP附件选择在同一Skill的相关页面之间共享，成功导出后按已确认的选择版本清除，关闭最后一个相关页面后清除。重启只恢复安全的页面导航与窗口布局，操作页会要求重新读取或预览，不恢复执行中的写入请求；操作记录页可直接恢复查看记录。窗口位置不合适时可使用标签栏“恢复默认布局”。

窗口右上角X只关闭该窗口，其他窗口和任务继续存在。关闭最后一个窗口或快捷键说明中的“退出全部窗口”，才进入全局保存与退出；不要用强制结束进程代替正常关闭。

## 操作记录与状态

侧栏的“操作记录”固定为一行入口，点击先显示最多五项浮动摘要，活动任务优先；不挤压分类栏。点击“返回操作”回到原页；明确选择“详情”或“查看全部记录”才进入详细标签，已有标签会复用。Esc或点击外部关闭摘要，后台任务继续。最近100条已结束任务的简明记录保存在现有管理数据库，重启后仍可查看；不保存令牌、文件正文或可直接重放的写入请求。记录随所属页面统一滚动。

记录页可搜索操作、阶段或错误，按全部、进行中、已结束及需关注筛选。每行显示时间、操作、阶段和状态；“查看结果”打开记录详情，“返回对应界面”定位对应Skill页签、客户端或仍在其他窗口的原页面。当前会话仍可查看已完成结果；重启后的旧预览需要重新读取，上传、更新、精简不会因查看记录再次执行。目标记录已移除时显示不可定位，不自动指向其他同名项目。“清空已结束记录”在各窗口同步移除已终结记录，活动任务继续保留，不改变Skill、管理关系或系统凭据。

关闭记录标签后任务继续执行；取消任务需使用该任务旁的“取消任务”，仅在排队或允许取消的读取中显示。将记录页移到独立窗口时保留该页搜索、筛选和滚动。其他窗口可各自打开记录页，任务数据共用，搜索与阅读位置分别保留；重启恢复记录页导航与滚动，搜索和状态筛选恢复默认。

读取与核对在后台执行时，可以继续切换界面、阅读其他 Skill、归类和收藏。同一 Skill 内容、同一远端分支写入或客户端资源发生冲突时自动排队；无需为一个无关读取等待整个界面。排队任务以及允许停止的读取可取消，正在等待网络响应时需到当前请求返回后停止；远端提交或文件应用进入关键写入后不强行中断。

关闭普通窗口先保存该窗口状态，其他窗口的任务继续；关闭最后一个窗口或退出全部窗口时，先协调所有窗口保存，取消排队和可停止的读取，等待已进入写入的任务完成，再保存退出。关闭或保存失败时保留窗口及错误提示；不通过强制结束来假装操作已经完成。

凭据创建、保存、移除的结果仍在凭据区显示；详情与操作页保留对应的关键反馈，不堆积历史消息。任务结果绑定原目标页面；切换Skill、页签或移动窗口后，旧响应不会替换另一页正在看的内容。遇到异常时先查看相应区域和操作记录页，再决定是否重试。

文件变化和Skill版本升级提醒在检查完成后更新：程序启动时、运行期间每30分钟及手动检查核对内容；返回窗口焦点时按15秒节流补查本地，遇到同一资源冲突时排队。各窗口共用应用调度器，不为每个窗口重复检查。因此保存文件后可能需要返回窗口或手动检查才能看到结果；程序没有实时监听每次文件保存。

GitHub待上传提示只用于已关联且已核对运行范围内的文件变化。首次没有历史的未知差异先标为待核对；未关联Skill、未选入范围的说明文件不泛称GitHub待上传。Skill版本提醒不代表已经下载、提交或升级管理器，文件操作仍需分别确认。

## 本页多选检查

勾选行首复选框，或用“选择本页全部 Skill”选择当前页。点击“检查所选”后，仅更新所选Skill的检查结果；同一来源的远端结果会在所选项之间复用。筛选、排序、修改每页数量或翻页会清空选择，不会把隐藏项带入操作。

检查结果会区分已核对与未完成项，请查看对应行的异常提示。检查不会直接下载或覆盖文件，也不会批量应用更新；每项下载、更新或提交仍需分别预览并手动确认。

## 外观和阅读

在设置的显示选项中选择明亮、夜间或护眼模式。护眼模式使用较低亮度的暖灰米色背景，降低大面积背景亮度并保持文字可读。界面缩放调整按钮、布局和文字整体大小；字号单独调整文字。默认文字为16px，缩放100%。缩放自动保存，主题与字号预览后保存；这些显示设置在各窗口共用，保存在管理数据目录，重启后恢复。高缩放时可以滚动页面，不会把操作按钮永久隐藏；每个页面的滚动和目录状态仍各自保留。

## 来源和安装

本地添加只登记原目录。远端添加先展示条目，只有确认下载后才创建运行文件。添加或完整刷新来源时，会尝试自动关联本地和远端的重复条目；关联本身不下载、移动或覆盖文件。

自动关联先读取两端`SKILL.md`中的真实内部`name`，要求相同且在本地、远端均只有一个候选；再要求两端目录标识与内部名一致，或者被核对的运行内容逐字节一致。显示名相同、文件夹看起来相似都不足以单独确定身份。歧义、托管目录、未核实身份或来源失败时跳过自动关联，保留独立记录和手动关联入口。合并后保留本地ID、原目录、运行范围与客户端连接，远端重复占位条目被移除，原文件保持不变；原因可在详情中查看。

自动关联确认的是来源对应关系，不代表已经安装过该仓库的某次提交。只有核实运行内容与固定提交的关系后才可建立相应基准，不能把首次观测推断为过去的安装历史。

有清单的仓库可按`runtime_files`下载。本地添加、刷新和读取文件清单时，程序按当前文件与可识别引用自动检查文件范围；依据充分且必要文件可用时自动记录。已有手动范围和旧版确认范围原样保留，新识别缺项会给出原因，供你检查是否调整。未知、缺失或读取失败不会冒充检查通过。

详情文件页和导出页按四个同级分组显示：

- **必要文件**：入口、调用配置、许可证、已识别包内依赖及需要随包的普通外部资源，按当前证据自动包含并显示异常。
- **可选包内文件**：Skill目录内的可选说明和附件，默认不选；勾选后加入本次ZIP。
- **可选外部文件**：明确可携带的普通外部文件，包括适用的共享规则；默认不选，本次勾选不改变长期用途。
- **环境与参考**：命令、目录、运行环境、历史和不能作为普通文件携带的引用，逐项说明可用性和处理原因。

必要外部资源合并到“必要文件”，可选外部文件保持独立，不嵌套在另一个文件清单下面。同一文件只有一个主条目，可展开查看引用位置和来源；核验异常直接显示，常规详情折叠。各组可分别展开、收起或从本页目录定位；数量、来源和勾选改变后仍保留对应组的折叠。下载、更新和提交的范围页继续分别核对必要项及可选项，内容区统一滚动。

“调整文件范围”是检查或手动修改长期文件范围的二级入口，供更新、下载和上传前核对；使用Skill无需先点此按钮。必要项展示识别原因，手动保存后沿用该范围。长期范围保存在管理数据中，本次ZIP勾选只决定这次携带的可选文件，两者分别处理。

未选的本地文件继续保留；上传后的精简是另一项有明确预览与校验的操作。导出独立计算必要文件，可选说明和附件默认不选；历史安装版本未知本身不阻止完整包导出。文件范围自动检查不安装外部工具或配置环境，也不表示已执行Skill、验证动态加载或完成模型调用；这些仍需在对应客户端和实际环境中核验。

可选目录格式沿用现有`skills`数组；每项可使用`source: "example/SKILL.md"`、`usage: "example/README.md"`、`runtime_files: ["SKILL.md", "scripts/run.py", "LICENSE"]`，顶层可标记`schema_version: 1`。未声明清单不等于整个仓库均为运行文件。目录协议不要求现有库立即改动。

## 更新与提交

“本地待上传”“远端待下载”“双方变更”“内容不同·待核对”“内容一致”和说明更新分别显示。变化页列出差异文件数量和精简路径，悬停可看完整摘要；不可只凭版本字符串判断新旧。

本地SKILL.md声明了根version或metadata.version时，检查也会刷新版本标签；没有声明或暂时无法解析时保留已有来源版本。版本显示不改变安装基准或内容比较结果。

没有安装历史时，首次看到两侧内容不同只表示差异，不代表某一侧较新。管理器保留双方各自首次观测；之后才据此区分本地变化、远端变化或双方变化。观测记录与安装基准分开保存，不会将一次观测说成过去的安装版本；缺少依据时仍需核对。

更新前检查预览的目录、提交及每个文件变化。预览后文件或分支发生变化，操作会拒绝，需要刷新重做预览。本地修改不会自动合并覆盖。先用现有编辑器处理差异，或将本地变更提交到自己的来源仓库，再刷新。

首次关联没有安装历史时，如果确认的本地运行文件与某个固定远端提交逐字节一致，可以在更新预览中确认该提交为基准，全程不替换文件。内容不一致时仍需先核对或提交自己的修改。

提交只修改明确勾选的文件，不会删除未下载的远端README。实际写入使用一个提交，并以非强制方式更新分支；并发变化会拒绝。提交成功而后续读取失败时，会保留成功信息并要求刷新核验，避免把已发生的写入说成从未执行。

## 客户端

默认入口为用户目录下`.agents/skills`（Codex）、`.claude/skills`（Claude Code）、`.cursor/skills`（Cursor）。现有同名文件夹或链接不被覆盖。Windows采用Junction；失败会报告，不改成复制。

客户端页按 Codex／Claude Code／Cursor 标签切换，只显示当前工具的全宽连接列表。顶部可以搜索名称与路径、筛选异常、检查连接及新增连接；每页默认10项，可切换20／50项。切换工具或搜索后回到第一页。

点击“连接 Skill”后搜索并多选本地 Skill，核对客户端与入口，再批量连接。已正常连接、托管只读或冲突的条目会明确说明。每项分别显示成功或原因，某项失败不撤销已经成功的项，也不自动覆盖已有目录；修正后可单独重试。

“客户端入口”是工具寻找 Skill 的位置，“原目录”才是实际文件。用户目录在 C 盘时，轻量 Junction 可以指向 D 盘原 Skill；链接本身只有少量文件系统记录，不会复制整份 Skill。路径详情可查看完整入口、原目录、连接方式与最近检查时间。目录存在或链接有效不代表模型已经实际调用。

管理器只负责提供文件。客户端本身的发现、启用及调用，需在相应客户端验证。移除管理记录不删源码；有连接时先断开。首版没有原文件删除按钮。

## 文档、分享和凭据

文档可切换安装提交与最新提交；相对Markdown和图片从同一仓库经后端读取。私有仓库令牌不会交给前端图片URL。文件链接打开前限制协议，远端HTML不会执行。

ZIP默认包含当前识别的必要运行文件、许可证和机器可读来源摘要；可选文件仅在本次勾选时加入。固定提交链接不会授予别人私有仓库访问权。导出不覆盖已有文件，且不能导出到原Skill内部。

v0.1.7起，默认ZIP名称为Skill内部名，例如paper-write.zip；包内继续保留原相对路径，不另加runtime或Skill外层文件夹。可以在文件页勾选本次附件，一并导出本地或GitHub内容。同路径两边都有时保留本地内容，远端独有附件固定到显示的提交后读取进ZIP，不长期复制到本地。

访问令牌在应用设置中输入并存入Windows凭据管理器。令牌权限在GitHub设置中决定，应用中的读取／写入选择只说明所需权限。

“创建令牌”会用默认浏览器打开已预填的细粒度令牌页面。进入GitHub后，在 Repository access 选择 Only select repositories，只选要管理的仓库，再点击 Generate token。把生成的值直接粘贴回管理器的访问令牌输入框，点击保存凭据。这里不使用SSH公钥；不要填入SSH／Deploy keys表单，也不要把生成值发送到聊天。遇到登录或验证要求时，在GitHub页面自行完成。

“创建令牌”负责打开创建页面，不代表令牌已经生成或配置成功。浏览器未打开时可用“复制创建链接”，再在浏览器地址栏粘贴。保存凭据后，应检查一次目标仓库以确认权限；GitHub连接器本身不提供个人访问令牌创建接口。

生成后立即点击令牌旁的复制按钮，再粘贴到管理器并保存。令牌详情页不再提供原值；若离开生成页面且没有复制，使用“重新生成令牌”，复制新值后重新保存凭据。重新生成会替换旧值，其他使用该旧值的程序也需要更新。

## 故障与恢复

- 网络或凭据失败：保留现有文件和最后一次状态，修复后手动刷新。旧状态不能当作最新检查结果。
- 读取长时间没有结束：先查看任务阶段及网络诊断，可以继续处理无冲突项目；读取允许取消，当前网络请求返回后停止。GitHub 限流按服务端提示延后，不持续重复请求。
- 编辑器占用文件：关闭相关文件再重新预览；失败更新会尝试恢复原内容。
- 意外退出：启动时检查`recovery`下未完成的事务并恢复。恢复时若发现之后又有新编辑，保留新编辑并显示人工核对提示。
- 恢复原始字节保存在管理数据目录的`recovery/<事务ID>/before`，对应`journal.json`记录目标与摘要。先保留当前新增内容再恢复；不要直接整目录覆盖。
- 恢复材料和记录不自动删除。程序目录、数据目录和原始Skill目录各自独立，卸载或清理时应分别核对。

首次启动默认使用可执行文件旁的 Skill_Manager_Data。现有路径继续保留，设置页显示实际生效位置；v0.2.1 可预览并迁移程序管理的数据与缓存，先复制校验再切换，旧文件保留。以`skill-manager.exe --data-dir <绝对目录>`启动会临时锁定目录，这不会迁移其他位置已有的数据。

也可在可执行文件旁保存UTF-8文本data-directory.txt，一行写入绝对目录或相对程序目录的路径。优先级为命令参数 > 环境变量SKILL_MANAGER_DATA_DIR > storage-paths.json保存配置 > data-directory.txt侧文件 > 默认目录。读取失败或格式无效会停止初始化，避免意外打开空数据库。管理数据与源码放在同一根目录时，应忽略manager.sqlite3及其临时文件、recovery、webview和侧文件，再检查Git清单。

## 分类与侧栏快捷操作（v0.1.5）

每项Skill只有一个主分类，分类平铺。点击分类区“＋”创建；分类菜单可重命名、调整顺序、移除。移除前显示成员数量，确认后只转为未分类，不删管理记录或原文件。分类信息仅保存在管理数据，不写GitHub。

从行首拖动柄拖到分类：已勾选行携带本页全部勾选项，未勾选行只归类该项。拖到“未分类”解除归属；也可用“归入分类”菜单。成功后可撤销最近一次归类。分类切换回第一页并清空选择，可与搜索、来源、状态组合。侧栏数字为分类总数，主区显示当前筛选结果。

Ctrl＋滚轮每格5%，Ctrl＋加减号同样调整，Ctrl＋0恢复100%；范围80%–160%，设置页可输入精确整数。缩放自动保存，字号独立；主题、字号仍需保存显示设置。

顶部按钮收起／展开侧栏。分界线可拖动，获得键盘焦点后可用左右键调整，双击恢复224px；范围200–420px。收起保留72px图标栏与分类入口。宽度和折叠状态分别自动保存；窄窗或高缩放空间不足时临时收起，恢复空间后沿用原设置。设置中的“恢复默认布局”仅恢复侧栏宽度和折叠状态。

## v0.1.6 归类、菜单与状态

勾选后，从已选行名称、说明或空白内容拖动，会携带本页全部勾选项；小点阵仍可拖单项。复选框、来源、编辑／更新／查看、星标及菜单按钮保留原动作。取消拖动不改变归属；失败保留勾选。分类可用专用柄拖动排序，固定入口不移动。

分类“…”与“归入分类”使用浮动菜单，不挤占列表。点击外部、按Esc或执行动作关闭；上下键选择、Enter执行，Esc返回入口。菜单较长时可在菜单内滚动。

列表行获得焦点后，空格切换勾选，Shift＋空格或Shift点击进行本页范围选择，方向键移动行焦点，Ctrl＋A只选本页。搜索框、编辑输入和弹窗保留自己的按键行为。切换分类、筛选和页码继续清空本页勾选。

星标收藏仅改变管理信息；侧栏收藏入口汇集不同分类中的收藏项，取消收藏不改变原分类。收藏、分类和排序均保存在现有管理数据目录。

“内容一致”表示最近比较范围中的文件摘要相同，不表示整个目录、仓库或此刻远端最新内容完全相同。悬停或展开详情中的“比较依据”可查看文件范围、提交、本地／远端成功检查时间、清单和基准。运行清单未确认会明确提示；旧记录缺少专用时间显示未知。返回焦点通常只检查本地，不能据此声称刚刚检查GitHub。

“本地额外文件”表示文件未纳入当前比较范围，请自行核对是否纳入清单，不等于自动待上传；真实运行文件修改仍为“本地待上传”。说明更新、远端更新与检查异常分别展示。远端失败时不继续用绿色内容一致冒充当前结果。

## v0.1.7 文件、附件与来源信息

文件页先显示本地清单，再补充GitHub文件，标明“本地”“GitHub”“本地＋GitHub”，同时显示本地、远端和远端独有数量。未关联、尚未读取、失败与确实为空分别提示；失败时仍保留本地可用清单，不把远端未知当作0项。固定提交结果在本次运行内存中复用，可用“刷新文件清单”重新读取。

必要运行文件与可选说明两组仍可折叠。“管理运行文件”打开本地实际文件清单：必要项锁定，按需要加入本地可选文件，再点击“确认运行文件”长期保存。原有下载、运行更新和提交范围仍单独核对；没有本地文件的远端项不能直接保存成已安装运行范围。

文件页的“本次附加选择”与上述运行清单分开：勾选本地或GitHub附件后，可用“导出所选附件”查看运行／附加／联网数量，再选择保存位置。新页面默认不选；同一标签切换或移窗保留，成功导出后清除该次选择，关闭详情页或在同一详情中更换Skill会清空。阅读、勾选、导出不会修改运行清单或安装基准。文件预览默认本地优先；可切换“本地版本”“GitHub版本”。远端预览标明自己实际读取的提交，后台刷新不把旧内容冒充新提交；手动刷新会使旧请求失效。

“下载到本地”仅处理所选远端独有文件，先显示路径和内容预览，确认后新增至现有Skill目录；已有同名文件、预览后新出现文件和期间修改均受保护。失败使用原有事务恢复机制。不覆盖本地定制，不把下载一份说明当成运行更新，不推进安装基准或自动标记内容一致。下载后的可选文件仍可按需加入运行范围，也可以继续作为额外文件保留。

来源页的依赖与验证说明读取本地SKILL声明、GitHub目录索引及README的依赖／权限与验证／局限章节。展示来源原文、文件、提交和独立文档读取时间，支持查看原文。本地原文入口读取真实本地文件，远端入口保持固定提交。读取失败显示未完成和重试，不直接称未提供；来源成功读取且缺少对应声明时才标明未声明。

来源里的依赖声明不表示本机已经安装，来源验证摘要也不表示管理器已在本机调用验证。客户端的发现、链接和实际调用继续分别显示。本版不自动安装依赖、不探测或启动外部模型。

## Ctrl＋Z 管理撤销

按Ctrl＋Z或点击侧栏“撤销”，可撤销最近一次归类、分类创建／重命名／移除／排序及收藏；连续按可回退本次运行最近20步。按钮提示将撤销的操作。移除分类的撤销会恢复原分类顺序和成员，分类操作不移动原文件。

搜索框、文字输入、选择控件与弹窗不截获为管理撤销，保留各自原有按键行为。相关管理保存冲突时等待；保存失败或相关记录变化时保留当前数据并显示错误，能够重试时可再次操作。撤销只恢复相关分类和收藏字段，不回退期间产生的文件检查结果、来源、连接或其他设置。重启后保留最后保存的数据，撤销历史重新开始。没有加入重做、显示设置撤销、文件恢复或远端提交撤销。


## 上传、本地精简与恢复（v0.1.8）

在本地Skill详情选择“上传到GitHub”；首次上传选择已添加的仓库、目标分支和仓库内目录。已关联项选择“上传本地修改”。默认选择必要文件，说明和附加文件另外勾选。私有来源需要该仓库的Contents读写权限；预览展示文件内容和目标，应用前再次校验本地与远端。

“上传后仅在GitHub保留可选文件”默认启用。预览列明本次选中、上传成功后准备精简的本地完整路径。只有固定提交中的文件内容独立读取一致、本地仍未改变且当前不属于运行必需时，才删除该本地文件。未上传、读取失败、不能判断必要性、已改动、正在使用、无法稳定核对文件或无法保存恢复记录时，保留原文件；不删除父目录。远端已有相同内容时可校验后精简，不创建空提交。未下载的README不作为远端删除请求。

结果分别显示上传提交、删除及保留数量和原因。上传成功后即使后续检查失败，也不会误报提交失败或自动重复提交。“恢复附件”根据上传收据中的固定提交预览恢复当前缺失文件，不覆盖后来新增的同名文件。收据在独立管理目录，保存摘要与来源，不保留第二份附件内容。它与Ctrl＋Z的分类／收藏历史独立。

## 依赖与比较证据（v0.1.8）

“核对运行依赖”集中检查每项结构、必需引用和当前内容；明确完整项自动记录运行清单，保留此前已选范围。历史来源、示例、外部配置与工具单列且默认折叠；真实包内缺项和不能判断的引用明确提示。结构核对不等于执行脚本或验证模型调用，不自动安装依赖。

文档中用于执行的命令块仍会识别必要脚本；Markdown示例不会被当成已安装资源。脚本自身相对路径、调用配置资源及可识别的本地导入属于包内检查；命令行输入、工作目录文件、运行时生成物及临时测试数据分别标明用途，不要求把它们复制到Skill目录。动态内部读取仍需核对。导出或精简遇到真实包内缺项、不可读取的必要文件或不明确的内部依赖时会保留文件并提示，不能通过隐藏提示代替补齐。

“内容一致”只说明最近核验的完整比较范围相等。上传后若分支又推进，固定提交中的附件即使可以校验和恢复，仍会保留“需重新检查”状态；精简成功不会把过期比较改成已同步。

比较基准是当前完整同范围内容相等的固定提交，记录建立方式与时间。历史安装提交仅由真实下载安装／更新事件记录；旧比较基准不补造历史。文件或范围变化、必要摘要无法读取时，原自动核验证据失效，之后按当前内容重新核对；仅本地检查和离线检查也遵循此规则，保留人工选择的文件范围。仅说明级信息不触发“需关注”；真实差异、缺项和异常仍会显示。

## 已有客户端入口（v0.1.8）

启动和刷新会按真实目标识别已有同源链接；重复连接直接登记。原位目录只标记可用，不创建自链接。已有普通副本、不同目标或断链不覆盖，显示中文原因和实际／预期路径。连接有效不表示已实际调用。

管理器创建的链接可断开；已有链接默认“移除管理记录”，原链接继续存在且不会立刻被重新扫描登记，显式连接可恢复管理。要真正解除已有链接，选择单独预览，确认完整位置与源目录后应用；链接身份或目标变化会拒绝旧预览。Skill原文件保留。

## 网络、读取速度与诊断（v0.1.9）

说明、文件清单和核对分为独立后台读取，本地内容先显示。已读取的固定提交、文件和图片在本次程序内存中复用，相同内容的重复读取合并；分支检查仍向 GitHub 核验当前版本。内存缓存上限64MiB，不落盘为另一份 Skill，退出程序后释放。普通内容比较可根据已校验的 Git 对象摘要复用本地相同字节，上传后独立回读和精简核验仍重新读取真实远端，不用缓存代替。

设置中的网络模式可选自动、直连、手动代理。自动模式复用 Windows 静态系统／环境代理；手动模式填写实际 HTTP、HTTPS、SOCKS5 或 SOCKS5h 端点，不修改系统代理。需要账号密码时使用独立输入框，保存到系统凭据管理，不写进代理地址、普通设置或日志。PAC 脚本不会在管理器里执行；仅有 PAC 配置时，可提供实际代理端点或使用 VPN 的系统路由模式。

“网络诊断”分别对 GitHub API 与公开文件入口作小请求，显示状态、耗时与失败原因，不携带私库令牌。浏览器或 VPN 能访问网站并不直接证明管理器当前使用了相同链路；公开入口诊断成功也不等于私库令牌权限正确，仍需检查目标仓库。

GitHub REST 请求全局按一个活动请求调度，前台读取优先；公开原始文件读取最多同时四项，避免粗暴并发触发限流。连接超时10秒，单次请求最多30秒；只读 GET 的连接／超时及502／503／504最多重试一次，写入不会盲目重放。取消在当前阻塞请求返回后生效；限流按服务端提示延后，任务记录会保留原因。

## 外部依赖、批量管理与仅 ZIP 打包（v0.2.0）

文件页的“外部依赖”分别显示用途、引用类型、引用位置、本地证据、GitHub证据和实际采用来源。本机存在且可读显示“本机可用”；远端显示仓库内路径及固定提交，未关联、未读取、读取失败与确认缺失分别说明，不把远端未知当作不存在。读取远端失败时仍保留本地可用信息。

同一已关联仓库、同一固定提交内，引用可精确定位时自动补充远端证据，包括Skill目录之外的普通资源。机器绝对路径和重名文件不按文件名自动绑定；有多个候选时，核对仓库路径后明确选择。“GitHub可用”表示能从该提交读取，不表示已安装到本地，也不证明外部环境或模型调用通过。

- **必要运行文件**：明确识别或由你确认的普通资源，默认加入ZIP，不必每次重新勾选。优先使用实际本地内容，缺少本地文件时可从已确定的GitHub固定提交直接入包。必要资源两侧均不能安全读取时阻止完整导出，可明确绑定实际单个文件。
- **可选附加文件**：默认不选，只有本次勾选时进入ZIP；新开页面、关闭详情或在同一详情中更换Skill会清空，成功导出后清除该次选择。标签切换和窗口转移保留未导出的选择。
- **环境与共享规则**：例如 CODEX_HOME、全局 AGENTS、机器运行环境和其他 Skill，以及调用时传入的 CLI 输入、工作目录文件与运行时生成物。它们不因被脚本读取就自动成为必要打包资源；可核验本机位置，不自动打包整个环境或其他 Skill。真正需要作为普通文件随包时逐项明确用途。
- **维护与历史信息**：例如 `_records`、旧备份与来源索引。保留说明，不当成当前必需资源，也不因旧路径不存在要求一直核对。

引用类型独立于上述用途。目录只核验位置，不递归打包整个目录；链接解析到当前Skill原目录时作为自身别名，已经对应包内文件时保留原包内位置并去重，可用“查看引用”定位。`/approve`等明确命令标为命令，不能作为文件绑定；真实`/目录/文件.json`路径仍按文件检查。不能执行的动作给出原因，仍能查看用途与原引用。

“绑定文件”登记明确选择的本地原件，或同一关联仓库固定提交中的文件；可预览路径后保存，不复制或移动原件，也不改变原先用途。重新映射只清除旧目标映射，保留用途，之后可选新目标。用途与映射保存在既有管理数据库；引用含义或绑定链接目标实质变化时需重新确认，同一文档别处的普通编辑不会让已确认用途无故失效。文件内容改动后读取当前摘要，不沿用旧证明。

管理区支持搜索和用途／状态筛选、勾选当前结果、范围选择，以及批量改用途、绑定、重新映射和复核。这里的管理勾选与ZIP附件勾选独立；批量绑定先逐项核对路径与来源。保存会重新核对引用，仍有效的项一起保存，过期或失败项逐条说明并保留供重试，不把一个失败项冒报为全部成功。复核只重新读取证据，不执行脚本、不安装依赖。未保存的搜索、勾选、用途与路径草稿随当前标签在本次运行中保留。

导出只产生你选择的最终ZIP。包内必要文件默认保留，可选说明和附件按本次选择；即使只在GitHub或外部原位置存在，也直接写入ZIP，不建立另一套资源文件、导出侧文件或临时目录。已是包内资源的文件保留原相对路径，包外普通文件使用`external/`下的相对位置，同一资源去重。管理器仍正常保存独立SQLite管理状态，这不是第二份Skill。原Skill文档、外部原件、共享规则与客户端链接不变，外部原件不参与上传后的可选文件精简。

管理器只在ZIP的副本中转换能够准确识别的静态文本文件引用。脚本硬编码、动态加载、代码示例或无法完整转换的引用仍列明需要对应环境；“文件已加入ZIP”不等于已经证明可迁移或运行成功。包内来源摘要记录相对位置、摘要和引用转换，外部绝对路径从其警告中脱敏。最终打包统一应用既有私有资源路径规则，不能通过包内路径或GitHub绑定把已识别凭据文件加入ZIP；普通配置与模板仍按原规则处理，没有新增内容扫描。必要包内许可证继续保留。
